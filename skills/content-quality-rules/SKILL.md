# SKILL-357：内容质量铁律

> 数据来源：27篇阿里云开发者公众号文章（Playwright抓取+自动拆解+LLM深度标注）
> 核心发现：**格式是壳，类比是魂** — 我们的提示词管格式（emoji/卡片/品牌色），但不管内容质量（类比/判断句/对比句）

---

## 一、标题铁律

### 标题必须包含以下元素之一（缺一不可）

**1. 类比型** — 把技术概念翻译成日常画面
- 公式：`[专业概念]：像[日常类比]一样[动词]`
- 例：端到端交付2.0：像工业流水线一样生产和交付需求
- 例：给野马套上缰绳：Agent Harness工程实践

**2. 反直觉型** — 颠覆常识
- 公式：`[看似A]但[其实是B]`
- 例：AI不缺智商缺纪律
- 例：Agent的每一次失败，都不是模型的问题，而是环境设计的债

**3. 数字冲击型** — 用数据制造紧迫感
- 公式：`[数字]+[结果/代价]`
- 例：5人7天干完20人数周的活
- 例：限流比降10倍

**4. 演进递进型** — 展示从A到B的跃迁
- 公式：`从[A]到[B]：[转化]`
- 例：从超级个体到超级组织
- 例：从RAG到Agent-native Knowledge

**5. 情境代入型** — 把读者拉入现场
- 公式：`当[主语][做某事]：[发生了什么]`
- 例：当Agent替你值班
- 例：当AI Coding Agent成为基础设施

### 标题生成规则

- 每次生成 **5个候选**（覆盖不同公式），人工选最优
- 标题长度控制在 **15-30字**
- 必须在 **0.3秒内** 让读者决定停留 → 类比/反直觉/数字至少有一个

### 标题评分维度（1-5分，0.5分一档）

| 维度 | 权重 | 5分 | 1分 |
|------|------|-----|-----|
| 信息密度 | 35% | 精准传达核心内容+技术栈+量化成果，无废词 | 信息含糊，看完不知讲什么 |
| 吸引力 | 30% | 精妙比喻/强烈对比/悬念/痛点共情，忍不住点击 | 平淡如水，毫无点击欲望 |
| 专业与流行平衡 | 20% | 技术深度+易传播，圈外也能理解价值 | 过于艰深或过于标题党空洞 |
| 结构与可读性 | 15% | 长短适中、节奏流畅、一眼扫读理解 | 关键词堆砌、断句奇怪 |

**CEO评分数据验证的标题公式排名**：

| 公式 | 均分 | 样本 | 结论 |
|------|------|------|------|
| 数字冲击型 | **4.67** | 3 | 🥇 最强公式 |
| 反直觉型 | **4.50** | 3 | 🥈 第二强 |
| 类比型 | **4.50** | 1 | 🥈 并列（样本少） |
| 演进型 | 4.00 | 3 | ✅ 可用 |
| 情境型 | 4.00 | 2 | ✅ 可用 |
| 概念解读型 | 3.50 | 7 | ⚠️ 平庸 |
| 方法论型 | 3.50 | 4 | ⚠️ 平庸 |
| 陈述型 | **2.50** | 3 | ❌ 避免使用 |

## 二、正文铁律

### 每2-3段必须出现以下之一（缺一扣分）

**1. 判断句** —「不是A而是B」穿透观点

高频模式（按频次排序）：
- **能力vs体系**：不是模型能力的问题，而是工程能力的差距
- **工具vs方法**：不是prompt，而是一份严格的操作手册
- **表面vs本质**：不是态度问题，而是认知盲区
- **限制vs释放**：不是给AI戴枷锁，而是给AI建立信用
- **角色vs定位**：不是"老板"，而是"项目经理+质检员"

**2. 日常类比** — 把技术翻译成画面

类比领域（按频次排序）：
- **工业**（流水线/质检/工位/工艺卡/数控机床）→ 最高频
- **法律**（宪法/判例/刑法/新法旧法）→ 第二频
- **游戏**（Boss/开团/Solo/MT+DPS+奶妈/装备门槛）→ 第三频
- **自然**（飞轮/雪花/水/树）→ 第四频
- **交通**（马/缰绳/引擎/刹车）→ 第五频

类比使用规则：
- 每个技术概念首次出现时，紧接一个类比翻译
- 类比必须来自读者日常生活，不能是另一个技术概念
- 一篇文章的类比最好来自 **同一领域**（工业类比贯穿全文 > 散装类比）

**3. 对比句** —「没有A的B像xxx」

- 没有 Harness 约束的 Spec 就像没有工艺卡的流水线
- 没有 Spec 承载的 Harness 就像写满规章制度的白板
- 没有自检的编码就像厨师给自己的菜打分

## 三、段落结构铁律

### 每个段落内部遵循6步公式

```
1. 一句话定义 — 干脆利落，不铺垫
   例：「Harness干的就是这件事——定义约束体系」

2. 类比翻译 — 紧接定义，1句话翻译成画面
   例：「一匹好马如果没有马具，跑起来方向不定」

3. 分层展开 — 2-4层递进，每层1段
   例：原则→宪法→规则→判例

4. 对比强化 — 有/无对比，或新旧对比
   例：「没有Harness vs 有完整Harness」

5. 案例/截图 — 具体证据
   例：「[图：spec文件夹实拍]」

6. 金句收尾 — 1句可以单独截图发朋友圈的总结
   例：「Spec+Harness是端到端交付2.0的脊梁骨」
```

### 文章宏观结构模板

**4段式（短文/小红书适用）**：
```
[钩子段] 痛点N连击 + 判断句（不是A而是B）
[核心段] 类比翻译 + 分层展开 + 对比强化
[价值段] 清单/框架/命令（收藏点）
[钩出段] 串场钩子 + CTA
```

**7段式（长文/公众号适用）**：
```
1. 导读 + 免责声明
2. 痛点段 — 现状N个问题
3. 判断句 — "真正的瓶颈不是X而是Y"
4. 类比段 — 核心类比贯穿
5. 设计原则 — "基于X的能力下限去设计"
6. 主体展开 — N个子课题 × 详细展开
7. 展望 + 收尾
```

## 四、文风铁律

| 规则 | 说明 | 反例 |
|------|------|------|
| 人称 | 「我们」(团队实践) 或「我」(个人判断) | 用被动语态或第三人称 |
| 语气 | 判断式、自信、不回避问题 | 模棱两可、含糊其辞 |
| 幽默 | 克制的幽默（「抽卡」「雪花消逝」「打Boss」级别） | 段子手/网络梗 |
| 信息密度 | 每段都有观点或类比，零废话段 | 连续3段纯信息陈述 |
| emoji | 公众号：零emoji / 小红书：克制（段首1个） | emoji堆砌 |
| 禁忌 | 不要纯信息陈述 | "XX是一种技术，它可以做YY" |

## 五、质量自检清单

写完文章后，逐项检查：

- [ ] **标题**：5类公式是否命中至少1个？
- [ ] **类比密度**：每2-3段是否有1个日常类比？
- [ ] **判断句密度**：全文是否有3+个「不是A而是B」？
- [ ] **对比句**：是否有2+个「没有A的B像xxx」？
- [ ] **金句**：是否有3+个可独立截图发朋友圈的句子？
- [ ] **开头钩子**：前200字是否让读者想继续？
- [ ] **零废话段**：每段都有观点或类比，无纯信息段？
- [ ] **文风一致**：人称/语气/幽默是否统一？
