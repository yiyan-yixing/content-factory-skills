# SKILL-606: 公众号写作

> 从实战沉淀：用户读公众号的速度比读书快 5 倍。不是"写得不够好"，是"结构不对，用户没耐心找重点"。
>
> 核心原则：**先定结构，再填内容。结构对了，内容只做减法。**

---

## 一、写作铁律（先记住这 5 条）

| # | 铁律 | 为什么 |
|---|------|--------|
| 1 | **叙事链贯穿全文** | 标题 → 摘要 → 每节标题 → 结尾，一条逻辑线从头走到尾。用户扫一眼标题和摘要就知道值不值得读。 |
| 2 | **3 的法则** | 人类大脑对"3"最舒服。三件事、三个论点、三条线、三个行动——永远用 3 组织信息。 |
| 3 | **每段不超过 3 句** | 手机屏宽约 20 字/行。一段超过 6 行（约 120 字）用户就开始划走。一段讲一个点，讲完就换行。 |
| 4 | **400-600 字一张配图** | 纯文字超过 600 字没有视觉落脚点，用户疲劳度急剧上升。配图是"让眼睛休息 3 秒"的策略。 |
| 5 | **知识密度拉满，零废话** | 每句话必须携带信息量。没有"正如我们之前提到的""众所周知""值得注意的是"这类水词。一段如果删掉第一句不影响理解——删掉它。 |

### 知识密度的具体标准

一段合格的公众号文字，应该做到：

```
错误示范（废话多）：
"在当今这个AI技术快速发展的时代，开源和闭源的选择变得越来越重要。
正如我们之前提到的，黄仁勋最近发了一条推文，这件事情引起了广泛关注。
那么，这件事到底意味着什么呢？让我们来仔细分析一下。"
→ 3 句话，0 个信息点

正确示范（密度高）：
"黄仁勋在 X 上发了人生中第一条推文——不是晒新芯片，而是一封公开信。
初始签署方 25 家，最新已增至 50 家，OpenAI 和谷歌均在列，
Anthropic 和 Amazon 始终未签。"
→ 2 句话，5 个信息点（谁、做了什么、多少人、谁签了、谁没签）
```

### 知识密度自检

写作时每写一段，问自己：

- [ ] 这段删掉，文章会少一个信息吗？→ 删掉没影响的段落
- [ ] 这段第一句是铺垫还是信息？→ 删掉所有"在...背景下""众所周知""值得注意的是"
- [ ] 这段有没有可以合并到上下文的句子？→ 能合并就合并
- [ ] 这段的每个数字/名字/引用都有来源吗？→ 没有来源的数字删掉

## 二、标准六节模板（看完标题链就定了）

### 文章骨骼

```
标题：直给，暴露叙事链

【概要】事件 · 意义 · 行动 一句话讲清（80-120字）

一、事件   ─── 发生了什么（3 件事 / 3 个背景）
              ↓
二、核心   ─── 三个核心论点 / 关键信息
              ↓
三、立场   ─── 谁支持谁反对，为什么
              ↓
四、趋势   ─── 三条线决定走向
              ↓
五、行动   ─── 三件事你现在就能做
              ↓
六、收束   ─── CTA + 下一篇预告
```

### 每节规范

#### 概要（字数：80-120 字 ｜ 配图：0 张）

- **功能**：封面图之后、正文之前，一句话告诉读者"这是什么、讲了什么、为什么要读"
- **格式**：`**本文概要：**` 开头的加粗标签 + 正文
- **写作公式**：`谁/什么事 + 发生了什么 + （可选：为什么重要 + 你将得到什么）`
- **字数控制**：80-120 字，不超过 3 句
- **位置**：紧接封面图和叙事链摘要之后、正文第一段之前
- **示例：**
  > **本文概要：** 7月16日到24日，Kimi K3发布、OpenAI模型失控入侵Hugging Face、黄仁勋首发公开信联署50家——三件事在8天内接连发生。本文梳理事件脉络、拆解核心论点、分析各方立场，最后给你三件现在就能做的事。
- **注意**：概要只是路标，不剧透核心结论。让读者有"看完就知道了"的期待，不要替文章画句号。

#### 一、三件事（字数：400-600 字 ｜ 配图：1 张）

- **功能**：告诉读者发生了什么，建立信息基础
- **写法**：三件独立的事／三个背景／三个现象，每件 100-200 字讲透
- **每件结构**：一句话定性 → 关键事实 → 1 个数据/引用佐证
- **配图**：本节的代表性截图（推文截图、产品截图、新闻图）
- **字数控制**：总 400-600 字，三件事平均分配

#### 二、三个核心论点（字数：300-400 字 ｜ 配图：1 张）

- **功能**：深挖核心内容，回答"到底说了什么"
- **写法**：三个论点/三条结论，每个论点格式：**一句话标题** + 一段引文或事实
- **配图**：信息图／三要点卡片（Pillow 生成）
- **字数控制**：每个论点 80-120 字

#### 三、各方立场（字数：200-300 字 ｜ 配图：0-1 张）

- **功能**：谁支持谁反对，揭示利益格局。让读者从"知道发生了啥"到"看懂为什么"
- **写法**：聚焦 2-3 个关键方的动机分析
- **字数控制**：短小精悍，200-300 字，事实+逻辑推理，不煽情

#### 四、趋势判断（字数：300-400 字 ｜ 配图：0-1 张）

- **功能**：三条线／三个方向／三个判断——文章的核心洞见
- **写法**：三线并列，每线 80-120 字。给出判断，不只描述
- **配图**：可选，数据可视化／阶梯图
- **字数控制**：300-400 字

#### 五、你的行动清单（字数：200-350 字 ｜ 配图：0 张）

- **功能**：读者读完最想知道的"然后呢"——三件具体能做的事
- **写法**：三个行动项，每项 60-100 字。可含清单、自查表、计算框架
- **字数控制**：200-350 字，所有内容必须可执行，不写正确的废话

#### 六、收束 CTA（字数：50-80 字）

- **功能**：预告下一篇 + 关注引导
- **写法**：下一期预告 + 一句话关注理由
- **字数控制**：1-2 句

## 四、标题规则

### 标题四原则

1. **直给，不绕** — 标题直接告诉读者这篇文章讲什么、怎么讲。不设悬念，不故弄玄虚
2. **暴露叙事链** — 最好的标题看完就知道文章结构：`三件事 · 三个论点 · 三条线` 或 `从 X 到 Y：Z 的 N 个关键`
3. **数字锚点** — 标题中至少包含 1 个数字（25 家、8 天、50 家、3 倍）
4. **15-30 字** — 公众号文章标题推荐长度

### 标题公式

```
公式 A：事件 + 叙事链
  【黄仁勋首发公开信联署50家：三件事 · 三个论点 · 三条线——AI开源走到哪了？】

公式 B：从 A 到 B：C 的 N 个关键
  【从Kimi K3到黄仁勋公开信：AI开源运动的三个关键节点】

公式 C：事件 + 判断句问句
  【黄仁勋首发公开信联署50家：AI开源走到哪一步了？】
```

## 六、查重与真实性检查清单（发布前必过）

### 真实性检查
- [ ] 每条事实都有第一手资料来源（官方声明、官方公告、原文链接）
- [ ] 引用的推文/公告有具体 URL，不是个人首页
- [ ] 数据（定价、参数、时间）与原始来源一致
- [ ] "真实案例"必须有源可查，虚构案例必须标注"假设"
- [ ] 各方立场分析有事实依据，不是主观推测
- [ ] 没有引用国内媒体/创作者的二手报道作为信息源

### 逻辑检查
- [ ] 标题→摘要→每节标题→结尾，叙事链一致，不矛盾
- [ ] 每节功能明确，不与其他节功能重叠
- [ ] 三件事之间有关系说明（不是随意拼凑）
- [ ] 行动指南可执行，不是正确的废话
- [ ] 全文没有冗余段落（每段删掉试试，不影响逻辑？删）

### 发布格式检查
- [ ] 脚注标记 `[^N]` 已替换（微信不支持 Markdown 脚注）
- [ ] 图片使用 `<img width="100%">` 适配手机屏
- [ ] 图片 alt 描述完整
- [ ] 中英文专有名词拼写一致
- [ ] frontmatter `status` 已改为 `published`
- [ ] 所有外部链接可点且指向正确页面

## 八、写作流程（标准步骤）

1. **定选题** → 确认热点 + 第一手资料是否可获取
2. **建骨骼** → 六节标题确定（确保叙事链一致）
3. **填事件** → Section 一：三件事，每件 100-200 字
4. **填核心** → Section 二：三个论点，每点 80-120 字（引用原文）
5. **填立场** → Section 三：2-3 方，每方 60-100 字（基于事实分析）
6. **填趋势** → Section 四：三条线，每线 80-120 字
7. **填行动** → Section 五：三个行动，每项 60-100 字
8. **写结尾** → Section 六：50-80 字
9. **配图计划** → 确定 3-4 张配图位置和类型
10. **生成配图** → Pillow 生成或截取
11. **真实性核验** → 逐条过检查清单
12. **格式清理** → 脚注、图片 width、拼写、首行缩进
13. **最终审稿** → 整体通读后发给用户确认

---

> **记住：写得短比写得长难。每删掉一个没用的段落，文章就变好一点。**
