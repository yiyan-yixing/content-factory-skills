# SKILL-359: 类比翻译

> 从阿里云27篇（22个显性类比+66个隐性类比）+ 爆款案例提炼
> 验证结论：类比是最强增量质量杠杆（0→3个类比，文章质量从C升到A）

## 核心原则

**每个技术概念必须跟一个日常类比。** 不是"最好有"，是"必须有"。
读者放弃一篇文章，90%是因为某个概念没看懂就走了——类比是留人的最后一道防线。

## 类比构造公式

**标准版（公众号）：**
`[技术概念]——像[日常场景]，[具体动作]，[结果/感受]`
> 截面选股零增益——像没有足够样本的民意调查，结论不可信

**精简版（小红书，1句话）：**
`[技术概念]像[日常场景]——[结果]`
> 信号太弱像GPS一格——到了也晚了

**对比版（两相对照）：**
`[没有A的B]像[日常场景]——[后果]`
> 没有Harness约束的Agent像没有缰绳的野马——跑得快但方向不定

## 密度规则

| 平台 | 类比密度 | 位置要求 |
|------|---------|---------|
| 公众号长文 | 每2-3段1个 | 每个大概念首次出现时必须有 |
| 小红书短文 | 全文2-3个 | 开头段1个+核心段1-2个 |
| X Thread | 每条核心tweet可含1个 | 首条hook必须有 |
| 知乎 | 每500字1个 | 比公众号更学术化，但必须有 |

## 自检清单

- [ ] 全文0个日常类比？→ 不合格，至少加2个
- [ ] 每个技术概念首次出现时跟了类比？
- [ ] 类比是否0.3秒内能脑补出画面？（"协同"不行，"开团打Boss"行）
- [ ] 类比是否和目标读者匹配？（别给产品经理用"梯度下降"类比）
- [ ] 是否有对比句？"没有A的B像xxx"
